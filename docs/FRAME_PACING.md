# Windows 弹幕帧节奏

## 实现

- 默认 D3D11 模式下，`maxFps=0` 使用 Qt 的显示刷新驱动。透明覆盖层通过公开的 `QSurfaceFormat::setSwapInterval(0)` 提交，避免 Windows 的更新请求已经跟随 DXGI 垂直同步后，D3D11 在开始帧时再次等待交换链。
- 限帧使用单调时钟、固定相位的纳秒截止时间，迟到时跳过过期帧，不逐帧累积唤醒误差。Windows 高精度 waitable timer 通过公开的 `QWinEventNotifier` 唤醒 GUI；不可用时回退到精确 `QChronoTimer`。不忙等，不更改系统计时器精度或进程优先级。
- 场景同步时仅修正滚动文字从快照计算到同步之间的位移，最多修正 100 毫秒；固定字幕不移动。暂停发布零速度快照，跳转仍由引擎重置，入场、避让和寿命不在渲染线程执行。
- mpv 生命周期监视保留已经验证身份的进程句柄，避免每 100 毫秒重新解析可执行文件路径。

### mpv 高负载模式

设置的“弹幕播放”提供 `mpvSmoothOverlay` 开关，默认关闭。启用后重新启动 DanmaX，Qt 软件渲染器在透明窗口内局部更新文字，包括分数 DPI。窗口仍覆盖整个播放器客户区，滚动、顶部、底部、调试信息及工具栏沿用原有坐标。固定字幕只有在位置发生变化时才使变换节点失效。该模式在创建首个 Quick 窗口前选定，同一进程的主面板采用纯色背景。[Qt 软件渲染与分数 DPI](https://doc.qt.io/qt-6.11/qtquick-visualcanvas-adaptations-software.html)

指定正值 `maxFps` 时按设定值调度。Qt 局部刷新在自动档使用高精度定时器按显示器刷新率分频，最高约 80 FPS。Windows 把分散的变更合入一个矩形上传。软件模式每 200 毫秒估算可见滚动文字的外接矩形，达到约 157 万物理像素时使用 40 FPS 以内的分频，面积减小并持续 2 秒后恢复。在 160 Hz 屏幕上分别为 80 和 40 FPS。诊断报告提供 `rasterMotionBoundsPixels` 与 `effectiveMaxFps` 供复核。[Qt 6.11 Windows backing store](https://github.com/qt/qtbase/blob/v6.11.0/src/plugins/platforms/windows/qwindowsbackingstore.cpp)

### Windows 桌面合成滚动

外部 mpv 会话在高负载模式、自动帧率、调试面板关闭时可以启用 `mpvCompositionScroll`。引擎决定轨道和入场时机，按当前样式与 DPI 栅格化文字。内容和样式相同的在屏文字复用表面。每条滚动文字入场时取得一段到左侧退场为止的水平位移动画，由 Windows DirectComposition 按同一时钟独立执行。其他弹幕的进出不会重写这段动画。160 Hz 屏幕每两个刷新周期移动一步。顶部与底部字幕继续由 Qt 绘制。[微软 DirectComposition 动画说明](https://learn.microsoft.com/en-us/windows/win32/directcomp/animation)

主显示器上，DanmaX 读取 [DWM 刷新时序](https://learn.microsoft.com/windows/win32/api/dwmapi/nf-dwmapi-dwmgetcompositiontiminginfo)，将每一步位移安排在两个垂直刷新时刻之间。这样起播时刻不会随机决定动画离下一个刷新边界有多近。仅在建立运动时钟、目标屏幕或目标频率改变时读取。非主屏、刷新率不匹配或时序不可用时，继续使用单调时钟。

一次同步最多为独立轨迹创建 4,096 个位移采样段，在屏独立轨迹合计最多保留 32,768 段。过长、过慢或同时入场的文字若超出预算，会共用一段同频率的四秒位移动画。三秒后即可续接；剩余路程缩短或旧弹幕退场腾出预算时，文字可以在同一时钟相位转入独立轨迹。

暂停、缓存停顿、恢复、调速和跳转都使用 mpv IPC 的状态。跳转清除旧轨迹，字体或 DPI 变化后重新生成表面。指定帧率、启动调试面板或关闭此开关会即时回到 Qt。创建原生设备或分配表面失败时，当前内容也可用 Qt 完整绘制。弹幕窗口的可见性、输入穿透和焦点仍由原窗口控制。

报告的 `desktopScrollActive` 表示合成层是否工作。`desktopScrollTargetFps` 是轨迹的目标频率，`effectiveMaxFps` 是引擎检查入场的频率。`desktopScrollVisuals`、`desktopScrollUploads` 和 `desktopScrollCommits` 分别记录原生滚动对象、像素上传和事务提交。`desktopScrollIndividualVisuals` 与 `desktopScrollSharedVisuals` 分别统计使用独立轨迹和共用动画的文字数，`desktopScrollIndividualKeyframes` 记录独立轨迹占用的总段数。`desktopScrollRefreshAligned` 表示本次是否用到了主屏刷新时序，`desktopScrollAnimationFps` 是该运动时钟实际采用的频率。实际运动间隔需要采样合成后的文字位置。

限帧部分参考 [Magpie StepTimer（固定版本）](https://github.com/Blinue/Magpie/blob/9e8e90274ba07f555bf87f09321dabdac97b1b4f/src/Magpie.Core/StepTimer.cpp) 的固定相位和高精度定时思路，但不移植其短时忙等。Magpie 的最低帧率用于没有新捕获帧时强制重绘，不能保证 GPU 负载下的 1% low，因此没有增加“最低帧率保证”设置。

Qt 行为依据锁定版本 6.11.0 的 `qwindowswindow.cpp::requestUpdate`、`qsgthreadedrenderloop.cpp::polishAndSync` 和 `qrhid3d11.cpp::beginFrame`；产品只调用公开 API。其他图形驱动、全屏组合及机器仍需单独验证。诊断时可用进程环境变量 `DANMAX_OVERLAY_SWAP_INTERVAL=1` 对比原交换间隔。

## 日志口径

设置 → 诊断 → **记录一次弹幕逐帧诊断** 可以记录当前或下一次弹幕播放。首个可见播放帧后采集 60 秒，停止播放、退出或关闭开关会提前保存。后台将内存中的数据一次写入数据目录的 `diagnostics/frames-*.csv`。记录上限为 65,536 个提交帧。也可在应用启动前于同一数据目录建立空文件 `diagnostics/next-frame-trace`，Emby 正常唤起的外挂会自动领取一次。

每行对应一次 Qt `frameSwapped`。软件模式在局部缓冲刷新后发出该信号。`max_fps` 是用户设置，`effective_max_fps` 是当时采用的调度上限。以 `id` 跟踪仍在场的最早一条滚动弹幕，`engine_x` 取 GUI 快照中的逻辑像素坐标，`draw_x` 取同步完成后场景节点的实际矩阵。只有固定弹幕或画面为空时记为 `id=0`。比较相邻行时，应核对 ID、播放/可见状态、媒体代次、时间轴重置数、窗口尺寸和 DPR。直接复用上次绘制结果的提交沿用上次的快照号和场景时间。

`tick_ns`、`snapshot_ns`、`scene_ns`、`begin_ns`、`sync_ns`、`render_ns`、`render_end_ns`、`swap_ns` 共用单调时钟，表示 GUI tick 开始、快照开始、场景坐标计算、Qt 帧开始、同步开始、渲染开始、渲染结束和提交回调。部分渲染后端缺少个别阶段的信号，相应值为 0。表头包含与系统时间对齐的锚点。记录不含弹幕文本、媒体标题和流地址。显示器实际呈现仍需单独观测。

`--report` 中的 `presentMeanMs`、`presentP95Ms`、`presentP99Ms`、`presentMaxMs` 来自渲染线程 `frameSwapped` 的单调时间戳，仅纳入内容序号变化的帧，保留最近 600 个间隔。`presentationIntervalsMs` 保留这些原始间隔供复算。不同报告的滑动窗口会重叠，不能拼接当成独立样本。

`onePercentLowFps` 在至少 100 个间隔后计算：1000 除以最慢 1% 间隔的平均毫秒数，样本数向上取整。它不是 P99 的倒数。`renderWaitP99Ms` 覆盖开始帧到场景同步的等待，`renderCpuP99Ms` 覆盖同步和命令准备，`renderSubmitP99Ms` 覆盖结束帧／提交，`guiDeliveryP99Ms` 是提交回调排队到 GUI 的延迟。它们不是 GPU 时间戳查询结果。

这些数据表示 Qt 帧提交时间，不能等同于显示器光学扫描输出或保证 DWM 显示了每个提交帧。`presentedPerSecond` 仍包含重复画面提交；`p95Ms/p99Ms` 仍为含维护路径的 GUI tick 间隔。报告不再写入可能包含流凭据的 SMTC 标题和标签。
