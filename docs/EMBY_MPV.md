# Emby → mpv → 外挂弹幕

此集成在 `legacy-mpv` 分支保留原有 SMTC 入口和字号／避让／帧率增强。网页的 MPV 按钮仍通过已有 `mpv-handler://` 或 `mpv://` 协议启动；不需要修改网页或服务器代码。

## 新电脑接入（0.2.5 起）

1. 完整解压 Windows 运行包，启动 `DanmaX.exe`。
2. 打开 **设置 → MPV 网页接入 → 配置接入**，选择本机 `mpv.exe`。
3. 填写 Misaka 兼容弹幕服务器地址及已有播放器 Token，点击 **保存并绑定协议**。已有配置的同一服务器可留空 Token 保留原值；更换服务器时需重新填写。
4. 在 Emby 网页点击 MPV，浏览器询问时允许打开 DanmaX。若 Windows 已指定其他默认程序，按界面提示在默认应用中选择 **DanmaX MPV**。

新入口直接由 DanmaX 原生执行，其他电脑不需要 Python、PowerShell 7 或手改注册表。它从所选 mpv 目录启动播放器，保留原有 mpv 配置；只有本次自动外挂启动才关闭内置弹幕的自动加载。可以关闭“自动显示外挂弹幕”，继续只从网页播放视频。

移动 DanmaX、换电脑或改变 mpv 位置后，再打开此入口选择程序并重新绑定。与 DanmaX 一起放在目录中的 mpv 路径可按相对位置保存；外部安装位置失效时可重新选择。服务器 Token 不会随 GitHub 包分发，需要在本机配置。

协议仅写当前用户的 HKCU，不请求管理员权限，不改视频文件关联。绑定前以原始注册表类型和字节备份现有协议；“还原原协议”恢复本机原绑定，不覆盖后来由其他程序接管的协议，也不把其他电脑的备份套用到本机。Windows 的 UserChoice 不会被绕过或删除。

还原恢复的是本机注册项。如果曾另外在 Windows 默认应用中手动改变选择，这项系统选择仍由 Windows 管理；需要时在系统设置中改回原应用。

配置仍保存在受当前用户及 SYSTEM 访问控制的 `external-player.json`，兼容原来的服务器配置格式，新增 `mpv.executable`。Token 仅在新输入框填写，界面不会读回已保存的明文 Token。

原生后台启动器复用同一进程身份校验和 IPC 后端。Emby 续播、字幕、10 秒进度回传以及停止后的已看／未看清理均保留；没有真实 IPC 位置时不提交伪造的停止位置，mpv 未能启动时不修改观看记录。关闭主界面不会关闭视频或停止后台回传。

`cache/external-sessions/latest.json` 保留最新原生启动会话标识，防止旧窗口的延迟元数据在新窗口关闭后重新打开外挂；单次会话描述在播放器退出时清理。该文件不含播放地址或 Token。

## 播放与匹配

点击 Emby 的 MPV 按钮后，启动器照常打开视频和字幕、恢复续播并回传 Emby 进度，同时把本次 mpv 的进程身份、独立 IPC 管道和条目元数据交给 DanmaX。弹幕匹配不会等待视频暂停。

唯一且信息一致的作品／季度／分集自动显示。多个来源、同名作品和特别篇需要首次确认；确认后记住单集关联。同季集号一致时，还会记住所选来源的分集表。服务器搜索中的临时 ID 会转换为可持续使用的关联，避免下次错误地复用过期搜索。

每次播放重新取服务器当前输出，保留 Pakku 合并、字号、颜色和位置。如果取弹幕失败，可重试或手动选源；有本集上次成功缓存时，会明确提示使用缓存。下载任务最多等待 120 秒。服务器返回的最新条数限制、来源错误及配额不会被绕过。

外挂绑定本次 mpv，而不是任意 `mpv.exe` 会话。窗口模式限制在客户区，移动／缩放／全屏时更新，最小化和切到其他应用时隐藏。暂停、倍速、跳转和停止来自 mpv IPC。连续打开多个 mpv 时只跟随最后启动的窗口，关闭最新窗口后不回到旧窗口。

关闭 mpv 会取消匹配、关闭覆盖层和工具栏。自动启动的专用 DanmaX 随后退出；原本已运行的 DanmaX 或后来切入的手动任务保留。关闭 DanmaX 不会关闭 mpv。用户主动取消弹幕后，不会因后续暂停／继续而自动打开。

## 旧 Python 入口兼容安装

先构建并部署 Release，再运行：

```powershell
./scripts/install-emby-mpv.ps1 -MpvDirectory '你的 mpv 目录' -PrivateProfile '本机私密配置.json'
```

私密配置格式如下；实际 Token 不应提交到 Git：

```json
{
  "enabled": true,
  "misaka": {
    "url": "http://你的服务器:7768",
    "token": "已有播放器Token"
  }
}
```

安装器先把原启动脚本和运行文件备份到项目 `.local/backups/emby-mpv-时间/`，再复制维护中的 Python 脚本到 mpv 目录。现有协议注册及 mpv 主配置不变。已有 Emby 续播与进度回传逻辑保留；本次启动只通过参数关闭 mpv 内部弹幕脚本的自动加载。

- mpv 目录 `danmax-bridge.json`：可执行文件、数据、缓存及会话目录。把 `enabled` 改为 `false` 可关闭自动外挂，后续启动继续使用原 mpv 工作流。
- DanmaX 数据目录 `external-player.json`：私密 Misaka 配置；安装器限制为当前用户及 SYSTEM 访问。
- `external-associations.json`：确认过的单集／季度关联，不含 Token。
- `cache/external-sessions/`：临时会话描述，不含播放地址或 Token。正常结束时由启动器清理。

界面和缓存使用不含凭据的服务标识；播放器 Token 仅用于真实请求。安装器不添加开机任务、监听端口或服务器服务。

## 回退

通常先把 mpv 目录 `danmax-bridge.json` 的 `enabled` 改为 `false`。完整回退时，关闭本次 DanmaX，按备份 `manifest.json` 恢复原启动脚本和 `runtime/` 文件；原本不存在的桥接脚本可在禁用后移除。不恢复服务器数据库，也不覆盖 mpv 的其他配置。

## 验证边界

0.2.5 的原生入口使用模拟 Emby 和真实独立 IPC 子进程验证了协议解码、字幕、续播、进度与停止回传、认证失败、无 IPC、启动失败及多个窗口的延迟元数据隔离。协议测试只写隔离注册表，覆盖重复绑定、移动后重绑、原始值类型恢复及后来接管的程序；没有替换开发机正在使用的协议。私密配置的当前用户／SYSTEM ACL 也有自动化检查。

本机 Release 的 21 项相关 CTest 通过；MPV 接入与原播放器配置界面在 Windows 原生平台测试通过，覆盖 800／520 逻辑宽度、键盘焦点可见、密码输入、错误及取消。云端另执行 MPV 配置的 offscreen 用例与干净部署启动检查。新原生入口尚未在另一台干净 Windows 电脑上以真实 Emby 网页完成验收；模拟服务器测试不等同于该项验收。

自动化覆盖进程身份、IPC、S02 匹配、来源歧义、临时 ID、关联复用、强制刷新、缓存回退、逐条小数字号、异步任务取消和停止清屏。真实服务器输出与原生启动／退出另外记录在 `out/validation/emby-mpv/`。

窗口移动、全屏、混合 DPI 及焦点仍需按实际设备验收；单元测试不能替代这些项目。实施期间用户按 Esc 停止了界面自动化，之后未继续窗口输入。

2026-10-24 检查时，服务器已启用最新发送 5000 条；《魔法禁书目录》S02E01 的最新池返回 HTTP 503，《凡人修仙传》189 集正常返回包含独立 `fontSize` 的输出。此为当次来源状态，不表示所有分集都可获取，也不等于客户端应改成全部输出。
